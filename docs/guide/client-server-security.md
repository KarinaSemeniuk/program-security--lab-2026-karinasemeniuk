# Клієнт сервер і межі довіри

React SPA відповідає за інтерфейс і попередню перевірку введення. Node API приймає остаточні рішення щодо ролі, власника, ліцензійної можливості, часу й перетинів бронювань. PostgreSQL зберігає облікові записи, відкликані/чинні сеанси, ресурси та бронювання. Клієнт не має доступу до БД.

Вхід: POST /api/auth/login з рівно двома полями email і password. bcrypt перевіряє пароль; сервер видає HS256 JWT на 900 секунд із iss=roombook, aud=roombook-web, sub та jti. Ідентифікатор jti має активний запис у sessions. Кожна захищена операція перевіряє підпис, алгоритм, час, видавця, аудиторію, чинність сеансу й актуальний запис користувача. Роль із тіла запиту або JWT не замінює роль у БД.

Токен міститься у HttpOnly SameSite=Strict cookie з Path=/api. У робочому HTTPS середовищі встановлюється Secure. SPA надсилає credentials=include. Токен не зберігається у localStorage. Вихід відкликає jti, тому скопійована cookie після виходу не працює. POST вимагає точного Origin і application/json; cross-site запити відхиляються. CORS лише обмежує браузерний обмін.

У локальній роботі HTTP дозволено лише на loopback. Робоча схема: HTTPS reverse proxy -> API на 127.0.0.1 -> PostgreSQL. Публічний каталог не розкриває особисті бронювання. Зміни ресурсів вимагають ADMIN; нотатки вимагають власника навіть для адміністратора. Секрети JWT і ключі нотаток залишаються на сервері, ключі E2EE залишаються на кінцевому пристрої.

Навчальний LibraryClient у labs/lab-10-11 незалежний від RoomBook: отримує непрозорий Bearer-токен на /auth/token, тримає його в пам'яті, повторно автентифікується перед завершенням дії та один раз після 401. Облікові дані передаються лише кінцевій точці автентифікації. Запити до невідомих маршрутів і перенаправлення заборонено. Запуск: LIBRARY_CLIENT_ID і LIBRARY_CLIENT_SECRET задаються через оточення; node labs/lab-10-11/library-client.mjs. Для браузерного клієнта відкрийте index.html через локальний статичний HTTP сервер.
