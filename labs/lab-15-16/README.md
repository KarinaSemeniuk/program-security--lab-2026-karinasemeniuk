# Контроль відновлення

Працюйте лише з окремою навчальною БД. Запустіть актуальний API з PORT у .env. Спочатку KEEP_QA_FIXTURE=1 node --env-file=.env labs/lab-13-14/check-security-block.mjs створює контрольні дані та приватний файл var/qa/ui-fixture.json. Файл не публікується і не додається в архів коду.

Задайте BACKUP_KEY_FILE на 0600 hex-файл із 32 випадковими байтами поза проєктом. Створіть копію: node --env-file=.env scripts/backup.mjs create .backups/recovery.rbbackup. Після цього запустіть node --env-file=.env labs/lab-15-16/check-recovery.mjs. Сценарій створює окрему базу roombook_drill_*, моделює втрату лише в ній, відновлює дані та запускає відновлений API на порту 3116. Поточна БД не видаляється. Тестова відновлена БД зберігається для перегляду.

За потреби QA_BACKUP_PATH і QA_FIXTURE_PATH змінюють шляхи. Не запускайте контрольний сценарій на реальних персональних даних.
